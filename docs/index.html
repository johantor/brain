Claude Code plugin · learns from every session

Make the same mistake once.

You correct Claude, and the next session makes the same mistake. brain reads each finished session, drafts a lesson from your own words, loads it into later sessions, and keeps only the lessons that help. No /learn step.

$ claude plugin marketplace add johantor/plugins
$ claude plugin install brain@johantor

It records from the first session. Run /brain:shadow on to draft lessons and /brain:learn on to load them; both start off.

How it works

Code decides when. Claude only drafts.

Hooks write the signals, rules in code decide when to reflect and what to keep, and a lesson is checked before it is stored.

  1. Record the frictionFailing calls, denied permissions, interrupts and corrections such as "no, …" go to a local SQLite file, scrubbed. Ask the brain skill what keeps failing, or run /brain:report.
  2. Reflect at a clean stopAfter friction, the first turn that ends clean asks Claude to draft at most two lessons from what you said. brain rejects scripts, URLs, paths and commands with arguments.
  3. Load, score, retireLessons load at session start. Each sits out about 30% of sessions, so brain can compare: one that helps is confirmed, one that does not is archived. Three on one tool become a skill.
Your control

Every change is yours to undo.

A session starts with one line that lists what brain changed since the last one. Every change is also in ~/.claude/brain/changes.log.

  • /brain:forget L12Stops a lesson for good, or say "forget that lesson".
  • /brain:pin L12Keeps a lesson, loaded first and never retired.
  • /brain:undoReverses brain's latest lesson change, an archive included.
  • /brain:forget S2Stops a skill. A draft skill waits 3 days before it goes live.

When the model changes, each lesson about a mistake sits out its next 5 sessions. If the mistake does not come back, the new model does not need the lesson, and brain archives it.

Privacy

It stays on your machine.

Prompts can hold client code and secrets. brain sends nothing anywhere.

  • Signals, not output. Tool output is never stored, so a fetched page cannot plant a lesson.
  • Scrubbed first. Secrets, URLs, paths, hosts and project names become placeholders.
  • Yours alone. ~/.claude/brain is mode 700. In a cloud session the hooks do nothing.
# ~/.claude/brain/lessons/L12.md, one file per lesson
---
type: "brain/lesson"
description: "Search with `rg`, not `grep -r`."
kind: "tool-habit"
scope: "global"
status: "draft"
verified: "process:holdout"
---
Requirements

Node, and that's it.

  • Claude CodeCLI, desktop or IDE extension, with plugin support.
  • Node.js 22.13+On the PATH that Claude Code's hooks see, for node:sqlite. No packages to install.
  • WindowsGit for Windows, so the hook runs in Git Bash.

Known gaps, such as a correction worded without "no" or "wrong", are listed in the README.
